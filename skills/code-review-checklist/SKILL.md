# Code Review Checklist

Use esta checklist ao revisar código.

## 1. Clareza
- O código é fácil de entender?
- Os nomes explicam intenção?
- Existe lógica escondida ou “esperta” demais?
- Há comentários tentando compensar código confuso?

## 2. Responsabilidade
- Cada função, classe, módulo ou componente tem uma responsabilidade clara?
- Existe mistura de regra de negócio, infraestrutura e apresentação?
- Existe acoplamento desnecessário?

## 3. Simplicidade
- Há overengineering?
- Existem abstrações antes da necessidade?
- O código resolve o problema real ou tenta prever um futuro incerto?

## 4. Consistência
- O código segue padrões do projeto?
- A estrutura combina com o restante da base?
- Existem estilos diferentes para resolver o mesmo problema?

## 5. Erros e bordas
- Erros são tratados?
- Casos nulos, vazios e inválidos foram considerados?
- Mensagens de erro ajudam?

## 6. Manutenção
- A mudança será fácil de alterar depois?
- Existe duplicação?
- Há risco de regressão?

## Saída esperada
Responda com:
1. Resumo geral.
2. Problemas críticos.
3. Melhorias importantes.
4. Ajustes opcionais.
5. Recomendações práticas.
